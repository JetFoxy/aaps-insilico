# W4 — вкладка what-if, SSE, i18n и ручная приёмка

Дата: 2026-11-23
Статус: **принят** — страница собирает импорт, оба режима, варианты и графики; ручной чек-лист
пройден на синтетическом Nightscout-стабе. Реальная линия CGM приходит в `start`-кадре SSE и
рисуется в обоих режимах, включая первый запуск `model`, без предварительного replay.

## 1. Постановка

По спеке §10 W4 — UI, SSE и i18n поверх API Task 9. Требовалось: форма подключения (URL,
read-only токен, дни, необязательный экспорт AAPS + пароль), сводка импорта, переключатель
`Replay | Model` с объяснением, редактор до 4 вариантов (алгоритм, SMB, веса autoISF, правки
профиля, копирование/сброс), SVG-график глюкозы с реальной и модельной линиями, бары
инсулина/SMB, линия IOB, таблица метрик, блок «что не воспроизведено», постоянная плашка
«Это не клинический прогноз» и кнопка удаления импорта.

Все строки — ключи `web/i18n.js` (RU и EN). Внешних JS/CSS-библиотек нет: только локальные
`style.css`, `whatif.css`, `i18n.js`, `whatif.js`. В API Task 9 добавлено только поле `real`
в `start`-кадр SSE; движки и остальные эндпоинты не менялись.

## 4. Токен и приватность

Токен и пароль передаются только в одном `POST /api/whatif/import` на локальный сервер.
Проверено на итоговой сборке в браузере:

- токена нет в `document.documentElement.outerHTML`, `document.body.innerText`, `location.href`,
  `localStorage` (список ключей пуст), URL запросов и консоли;
- токена нет ни в одном запросе, кроме тела импорта; в теле импорта ключи
  `url, days, token, prefs_text` — это единственная передача;
- после успешного импорта поля токена и пароля очищены; `prefs-file` сброшен;
- сервер логирует только путь `/api/whatif/*`, тело и токен в лог не попадают;
- `localStorage` используется только ключом `sim_lang` из существующего i18n.

Оговорка: при открытии DevTools вкладка Network показывает тело того самого запроса импорта —
иначе браузер не может передать токен серверу. Требование «токен не виден в Network» выполнено
в смысле «нет в URL, ответах, SSE и последующих запросах»; сама передача на `127.0.0.1`
неизбежна. Страница дополнительно предупреждает, что URL, токен и пароль идут только на
локальный сервер.

## 5. Ограничения

1. **Один браузерный прогон.** Полный сценарий (импорт → первый model 2 варианта → удаление)
   пройден на итоговой сборке; replay-ветка проверена отдельно (2 варианта и SMB off через API).
   Автоматического браузерного теста в репозитории нет — по брифу тест статический.
2. **Размер `start`-кадра.** Реальная серия передаётся целиком: для 3 дней это тысячи пар, для
   14 дней — порядка 20 тысяч; JSON заметно растёт. Для локального 3-дневного окна приемлемо,
   для больших окон стоит даунсэмплить или сжимать (вне рамок задачи).
3. **Синтетика.** Стаб не содержит `devicestatus`, поэтому паритет решений W2 в этом прогоне
   недоступен; это видно в предупреждении импорта. Числа §3 — иллюстрация работы UI, а не
   метрики пользователя.
4. **Одинаковые replay-варианты.** На синтетическом профиле и пустом экспорте autoISF on/off
   дали одинаковый инсулин; это поведение движка и пустых настроек, UI передаёт разные
   `algorithm` и `smb`.
5. **Docker не менялся.** `Dockerfile` уже открывает 8766 и ставит `requirements.txt`
   (включая `cryptography`), правка не требовалась. `docker-compose.yml` публикует 8766 на все
   интерфейсы; для строгой локальности публикацию стоит ограничить `127.0.0.1`, но это
   существующая конфигурация вне рамок Task 10.
6. **Не клинический инструмент.** Модельные TIR/TBR/LBGI — поведение виртуального субъекта,
   а не прогноз; плашка «Это не клинический прогноз» присутствует постоянно.

## 6. Вердикт

W4 принят: вкладка, SSE, варианты, графики, i18n и удаление импорта работают на синтетическом
трейсе; секреты не сохраняются и не попадают в URL, DOM, хранилище или консоль. Реальная линия
CGM приходит в `start`-кадре и рисуется в обоих режимах, включая первый `model`-прогон;
похожесть субъекта (`good`/`low`) переводится. API расширен только полем `real` в
`start`-кадре; движки не менялись.
