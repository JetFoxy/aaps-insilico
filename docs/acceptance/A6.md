# A6 — расширенная когорта, шум CGM и параметры алгоритмов

Дата: 2026-11-11
Статус: **принят** для когорты, шума и настроек; DynISF — запланирован, не подключён.

## 1. Зачем

Стенд упирался в три ограничения: 30 субъектов мало для статистики, шум CGM был зафиксирован
реальными остатками, а настройки autoISF брались из одного файла настроек. A6 делает все три оси
параметрами командной строки.

## 2. Расширенная когорта

`python/simcore/cohort.py::extend_cohort` добавляет к каждому из 30 базовых субъектов N копий с
лог-нормальным возмущением (σ = 0.15) только тех параметров, которые **не входят** в стационарное
состояние натощак:

- всасывание еды: `kabs`, `kmax`, `kmin`;
- всасывание инсулина: `ka1`, `ka2`, `kd`;
- подкожная глюкоза: `ksc`.

Стационар подкожного инсулина пересчитывается аналитически из уравнений модели:
`Isc1 = insulin_ss / (ka1 + kd)`, `Isc2 = kd · Isc1 / ka2`, где `insulin_ss` берётся из базового
вектора. Поэтому каждая копия стартует с той же глюкозой натощак, что и базовый субъект.

Проверка: 180 мин на собственном базале, максимальное отклонение от `Gb` — **2.1·10⁻¹⁰ мг/дл**
(у базовых субъектов 1.2·10⁻¹⁰). Тест: `tests/test_cohort.py`.

`Vmx`, `kp3`, `BW`, `Gb`, `u2ss` не возмущаются: их популяционный вектор проприетален, а
переравновесие не валидировано. То есть когорта расширяется по всасыванию, а не по
чувствительности к инсулину — это записанное ограничение, а не скрытое допущение.

Использование: `--cohort-copies N` (30 → 30·(1+N)), `--cohort-seed`. При N = 3 — 120 субъектов.

## 3. Шум CGM

`python/cgm/noise.py`:

| Модель | Что делает |
|---|---|
| `residuals` (по умолчанию) | блочный реплей реальных остатков, `--noise-scale` масштабирует амплитуду |
| `ar1` | `x[k] = ρ·x[k-1] + ε`, `--noise-sigma`, `--noise-ar1` |
| `white` | независимый гауссов шум, `--noise-sigma` |
| `facchinetti` | опубликованная модель ошибки (Facchinetti 2014): AR(2) + дрейф калибровки |
| `dexcom` | та же структура с параметрами Dexcom G6 (Vettoretti 2019) |
| `none` | без шума (для отладки) |

`--noise-scale` применяется ко всем моделям, включая реальные остатки. Модели `facchinetti` и
`dexcom` реализованы по статьям и сверены с эталонной реализацией LoopInsighT1 (MIT); на реальных
трейсах они дают σ 2.46 и 1.36 мг/дл против 2.8–4.4 у записей (A8).

### 3.1 Ошибки объявления еды

Кроме режимов `fcl`/`announced`, сценарий задаёт ошибки объявления:

| Поле | Смысл |
|---|---|
| `announce_amount_error_frac` | объявленное количество = фактическое × (1 + δ) |
| `announce_time_error_min` | объявленное время = фактическое + δ, мин |
| `announce_lead_min` | объявление сделано раньше на δ, мин |

Физиология всегда ест фактическое количество в фактическое время; алгоритм видит объявленное.
Готовый сценарий — `announced-error` в `a2_matrix.py` (+20 % углеводов, +15 мин, опережение 10 мин).

## 4. Настройки алгоритмов

`--pref KEY=VALUE` (можно повторять) переопределяет любую настройку AAPS для всех прогонов:
веса autoISF (`bgAccel_ISF_weight`, `bgBrake_ISF_weight`, `lower_ISFrange_weight`,
`higher_ISFrange_weight`, `pp_ISF_weight`, `dura_ISF_weight`), границы `autoISF_min/max`,
SMB-параметры (`openapsama_smb_delivery_ratio`, `smbsmbmaxminutes` и т.д.). Тип значения
определяется автоматически (int → float → bool → str).

Опции общие для `a2_matrix.py`, `fault_matrix.py`, `export_demo.py` и `server/live.py`
(`python/runner/options.py`). Те же значения читаются из окружения (`SIM_COHORT_COPIES`,
`SIM_NOISE*`, `SIM_PREFS`, `SIM_PREFS_FILE`, `SIM_ISF_SOURCE`, `SIM_TEMP_MODE`, `SIM_VARIABILITY`,
`SIM_COMPARE`, `SIM_HOST`, `SIM_PORT`); приоритет — CLI, затем окружение, затем встроенные значения.

В live-UI параметры задаются на каждый прогон: панель «параметры прогона» (когорта, seed, шум и его
амплитуда, ISF rule/model, темпы, вариативность, SMB ratio, шесть весов autoISF и min/max).
Сервер валидирует и применяет их к конкретному прогону; эхо параметров возвращается в кадре
`start` и показывается в футере.

## 5. Пример настроек вместо приватного файла

`data/fixtures/prefs.example.json` — курируемый набор настроек APS/autoISF плюс определение
инсулина. Важная деталь: `insulinEndTime` и `insulinPeakTime` в AAPS хранятся **в миллисекундах**
(DIA 8 ч = 28 800 000, пик 45 мин = 2 700 000). Первая версия примера использовала минуты
(480/45) — алгоритм считал, что инсулин действует 0.008 ч, и удваивал дозу: TBR 34 % вместо 0.
После исправления пример воспроизводит реальные настройки бит-в-бит на контрольных прогонах:

| Прогон | TIR | TBR | Доза, ЕД | SMB |
|---|---|---|---|---|
| `adult#001`, announced 8 ч, off | 0.677 / 0.677 | 0 / 0 | 26.0 / 26.0 | 62 / 62 |
| `adolescent#001`, FCL 24 ч, off | 1.000 / 1.000 | 0 / 0 | 30.89 / 30.89 | 122 / 122 |
| `adolescent#001`, FCL 24 ч, on | 1.000 / 1.000 | 0 / 0 | 31.57 / 31.57 | 99 / 99 |

(первое число — реальные настройки, второе — пример).

## 6. DynISF

`DetermineBasalSMB.determine_basal` принимает `dynIsfMode`, но настоящий плагин перед вызовом
считает `variable_sens` из истории TDD (1 день, 7 дней, последние 24 ч, последние 4 ч) в приватном
`calculateRawDynIsf`, через полный граф сервисов (`TddCalculator`, `PersistenceLayer`,
`IobCobCalculator` и т.д.). Переписать формулу в мосте значило бы нарушить правило «алгоритмы не
портировать». Поэтому DynISF требует отдельного адаптера вокруг настоящего плагина и подачи TDD из
журнала доз симуляции — это следующий этап, а не текущий.

Что уже готово для него: `--pref` умеет менять любые настройки DynISF/SMB, а `DetermineBasalSMB`
доступен в том же AAPS-модуле, что и `DetermineBasalAutoISF`.

```bash
.venv/bin/python -m pytest tests/test_cohort.py -q

# 120 субъектов, шум в 1.5 раза сильнее, вес ускорения autoISF выключен
.venv/bin/python python/runner/a2_matrix.py --subjects 120 --workers 6 \
    --cohort-copies 3 --noise-scale 1.5 \
    --pref bgAccel_ISF_weight=0.0 --out out/a2_extended.json

# другой шум
.venv/bin/python python/runner/a2_matrix.py --subjects 30 --noise ar1 --noise-ar1 0.9 \
    --noise-sigma 3.0 --out out/a2_ar1.json
```
