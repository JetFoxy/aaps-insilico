политикой (`runner/profiles.py`): такие субъекты исключаются, fallback только по явному флагу.

- **A2:** 27 субъектов × 4 сценария × autoISF off/on;

- **A25:** 27 субъектов × 3 плеча × 1 сутки, gate.

Всё на чистом пине `74271a544b`, те же сиды и сценарии.

## 5. Вывод

1. **Исторические направления устойчивы:** удаление трёх fallback-субъектов не перевернуло ни
   A2, ни A14, ни A25.
2. **Абсолютные числа сдвинулись:** off-плечо стало заметно лучше (TIR 0.714→0.740,
   TBR 0.070→0.037, LBGI 2.18→1.05). Отчёты, цитирующие старые абсолютные значения, должны
   ссылаться на A39.
3. **Эффекты стали чуть меньше по DynISF** (−2.1/+3.2/+0.91 вместо −2.3/+3.7/+1.19), но
   порядок плеч тот же.
4. **Gate остаётся fail:** 0/1/3 тяжёлых, худший 240–385 мин/сут `<54`; это не свойство трёх
   субъектов.
5. **Системная политика теперь одна:** `profile_values`/`cached_profile_values` падают без
   feasible CR; `--allow-profile-fallback` — только для воспроизведения старых прогонов.
