# W2 — сверка replay с `openaps.suggested`

Дата: 2026-11-23
Статус: **не принят** — final_isf 498/1574; insulin_req 661/1574; rate 212/829; smb_on 1118/1575; factor:acceIsf 596/1574; factor:bgIsf 652/1574; factor:duraIsf 1266/1574.

## 1. Постановка

По спеке §4.4: baseline replay должен воспроизводить записанные решения `openaps.suggested` по `devicestatus` того же дня. Сверяются `finalIsf`, `insulinReq`, `rate`, `smbOn` и факторы `autoIsf`; допуски зафиксированы до первого прогона и в ходе приёмки не менялись.

## 2. Метод сверки

1. Трейс импортируется из Nightscout (W1): сырые точки CGM, лечения, профиль, записи решений. Импорт включает 8-часовой lookback до `window_start`; решения lookback не входят в знаменатель покрытия.
2. Baseline-вариант собирается из настроек стенда и профиля Nightscout; точки решения берутся из записанных `deliverAt` (5-минутная сетка — только если решений в трейсе нет), глюкоза не пересчитывается.
3. Каждое записанное решение сопоставляется с циклом replay по `deliverAt` с окном ±1 мин; без пары решение попадает в `unmatched`.
4. Для каждого поля считается доля совпадений в пределах допуска и максимальная абсолютная ошибка; `smbOn` сравнивается с фактом доставки SMB (`smb > 0`).
5. AAPS пишет в `openaps.suggested.autoIsf.finalIsf` итоговый множитель autoISF, а не абсолютную чувствительность; поэтому поле сверяется с множителем `aiv.finalIsf` из ответа моста, а не с `sens` (mg/dL/U).
6. Записи, где у поля нет эталона (`None`), в знаменатель `n` этого поля не входят: доля считается только по записям с ground truth.
7. `factor:iobThEffective` — производное значение моста (`max_iob` × порог IOB), а не динамический ограничитель AAPS; оно показывается для информации и в вердикт не входит.

## 6. Ограничения

1. Проверяется только baseline-вариант; контрфактические варианты W2 не покрывает.
2. Глюкоза в replay — реальный CGM, поэтому паритет характеризует решения, а не исходы.
3. Циклы с пропуском CGM и без пары по `deliverAt` исключены из процента и перечислены в §4.
4. Temp target реконструируется из лечений; exercise и неизвестные события не воспроизводятся.
5. Смена профиля применяется на своём времени: `profileJson` и процент из `profile switch`, плюс сегменты профиля Nightscout. Если в трейсе нет `profileJson`, переключение не применяется; счётчик — в §4.
6. Числа в отчёте агрегированные: значения глюкозы, время приёмов пищи и параметры инсулина не публикуются.
7. Шаг replay следует записанным `deliverAt`; 5-минутная сетка остаётся запасным вариантом для трейсов без решений. Расхождение полей на одинаковых точках времени — это разница входов replay и записи, а не ошибка сопоставления.

## 7. Причина расхождения: версия AAPS

Мост собран против upstream-пина `4.1-kmp-upstream-pumps-only@74271a544b`. Трейс записан
production-сборкой AAPS, которая новее: в ней есть raw-observation estimator
(`rawObservationEstimatorSupported`, `RAW_OBSERVATION_SOURCES`) и `autoISF` с IOB/COB/TDD.
В пине нет ни того, ни другого.

Диагностика на худшем цикле:

- записанный `acceIsf` −9.43, `bg` 162.9;
- replay `acceIsf` 0.64, `glucose` 167.5, `bgAcceleration` −2.16;
- статус моста на записанном ряде `bg` (3-мин) — `bgAcceleration` −19.94.

Расходится ряд статуса: production-сборка кормит UKF сырые 1-минутные наблюдения Sibionics, а
пин — 5-минутную сетку; формула `acceIsf` при этом верна. Замена сглаживания
(`smooth`/`smoothWithoutLearning`/raw/grid) на пине результат не меняет.

Вывод: факторный паритет на этом пине недостижим. Абсолютная сверка требует пересборки моста под
production-ветку; upstream-вариант остаётся на upstream-коде и сохраняет это ограничение явно.
