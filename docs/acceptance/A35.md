# A35 — ресемплинг когорты: насколько устойчив scorecard

Дата: 2026-11-26
Статус: **принят как оценка неопределённости**. Показывает, что 7/12 — точечная оценка, а
вклад отдельных подписей сильно различается. Не валидация.

## 1. Постановка

Использованы per-subject подписи A33 (30 субъектов, шаблонная еда, M3 off). 4000 bootstrap-
ресемплов когорты с возвращением (seed 20261126). Для каждого ресемпла: медиана подписи и
попадание в конверт TimSim с допуском ±10 % ширины диапазона; scorecard — число подписей в
конверте в этом ресемпле.

Это оценка неопределённости **состава когорты**, а не ошибки модели: физиология субъектов и
один seed фиксированы.

## 3. Вывод

1. **Разница «5/12 против 7/12» между конфигурациями — на грани шума ресемплинга.** 90 %
   интервал шириной в 4 подписи означает, что сравнивать конфигурации по одному числу
   подписей нельзя; сравнивать надо состав (какие именно подписи и насколько).
2. **Пять подписей устойчиво в конверте:** `tail`, `acf30`, `acf60`, `compress`, `noise`
   (P ≥ 0.88). Это и есть реальный результат стенда на сегодня.
3. **`hypo_rec` — хрупкий:** 51.25 при границе 50–59, P = 0.54. В A31 он был 45.0, в A29 —
   55.0; колебания вокруг границы — не сигнал, а неопределённость.
4. **`hypo_reb` устойчиво вне** (P = 0.002): это не случайность выборки, а отсутствующий
   механизм (A32).
5. **`diurnal` и `cv` в основном вне**, `drift`/`insulin_cv` — тоже; для `drift`/`insulin_cv`
   добавляется ограничение оценщика (A30).
6. Практически: отчёт о fidelity должен давать не только число подписей, но и P(в конверте)
   по каждой; иначе 7/12 выглядит точнее, чем есть.

## 4. Ограничения

1. Bootstrap по 30 субъектам не отражает неопределённость параметров модели и сида.
2. Допуск ±10 % ширины диапазона влияет на пограничные `hypo_rec`, `cv`, `outcome`.
3. Per-subject подписи посчитаны на одном прогоне 22 суток; междусуточная вариативность
   внутри субъекта не входит.
4. Числа с чистого пина `74271a544b`.

## 5. Воспроизведение

```bash
.venv/bin/python - <<'PY'
import json, numpy as np
from runner.fidelity import SIGNATURES, in_real_range
rows = json.load(open("out/fidelity_22d_template_paired.json"))["per_subject"]
rng = np.random.default_rng(20261126)
idx = rng.integers(0, len(rows), size=(4000, len(rows)))
for key, _ in SIGNATURES:
    values = np.array([r[key] for r in rows])[idx]
    medians = np.nanmedian(values, axis=1)
    print(key, np.mean([in_real_range(key, m) for m in medians]))
PY
```
