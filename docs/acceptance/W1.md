# W1 — импорт Nightscout и нормализация трейса

Дата: 2026-11-23
Статус: **принят**. Клиент, нормализация и расшифровка экспорта настроек собраны в
`python -m nightscout import`; токен, URL и пароль не появляются в выводе и в `--out`.

## 1. Постановка

По спеке §10, W1: «клиент Nightscout + нормализация + расшифровка экспорта настроек + сводка».
Приёмка: синтетический мок-сервер, тест «токен не в логе», тест расшифровки на синтетическом
файле, импорт 3 дней.

Задача W1 — получить из Nightscout воспроизводимый дневной трейс: точки CGM, лечения,
сегменты профиля, записи решений `openaps.suggested` и предупреждения о пропусках. Сравнение
с реальными решениями (replay-паритет) — это W2, здесь его нет.

## 2. Что импортируется

| Документ | Endpoint | Во что превращается |
|---|---|---|
| status | `/api/v1/status.json` | проверка доступности инстанса |
| profile | `/api/v1/profile.json` | `ProfileSegment`: базал, ISF, CR, целевой диапазон, зона |
| sgv | `/api/v1/entries.json` | `CgmPoint`: `ts`, `mgdl`, направление, сенсор |
| treatments | `/api/v1/treatments.json` | болюсы (loop/manual), углеводы, temp basal, temp target, profile switch |
| devicestatus | `/api/v1/devicestatus.json` | `DecisionRecord` из `openaps.suggested` |
| экспорт настроек AAPS | файл `--prefs` | `prefs_loaded: true`; расшифровка при `--password` |

Окно: `window_end` = момент запуска, `window_start` = `window_end - days * 86_400_000`. Все
времена — epoch ms. Единицы профиля приводятся к mg/dL, часовой пояс профиля сохраняется.

Сводка содержит только счётчики и строки предупреждений:

```json
{"entries": 864, "treatments": 26, "decisions": 145, "profiles": 1,
 "window_start": 1795168170433, "window_end": 1795427370433, "sensor": "Libre2",
 "prefs_loaded": true, "warnings": []}
```

`--out` — явный экспорт полного трейса в JSON, не кэш. В нём только нормализованные поля
(`entries`, `treatments`, `profiles`, `decisions`, `window_start`, `window_end`, `timezone`,
`sensor`, `warnings`), без URL, токена и пароля.

## 3. Синтетический прогон

Тест поднимает `tests/nightscout_stub.py` на `127.0.0.1`, отдаёт синтетический профиль,
одну точку CGM и пустые treatments/devicestatus:

```bash
.venv/bin/python -m pytest tests/test_nightscout_cli.py -v
```

```
tests/test_nightscout_cli.py::test_import_summary_has_no_token PASSED
1 passed
```

Трёхдневный прогон на том же стабе (864 точки по 5 мин, болюсы и temp basal каждые 6 ч,
решения каждые 30 мин, сенсор `Libre2`, plaintext-экспорт настроек):

```bash
PYTHONPATH=python .venv/bin/python -m nightscout import \
    --url <ns-url> --token <token> --days 3 \
    --prefs <prefs-file> --out <trace.json>
```

```json
{"entries": 864, "treatments": 26, "decisions": 145, "profiles": 1,
 "window_start": 1795168170433, "window_end": 1795427370433, "sensor": "Libre2",
 "prefs_loaded": true, "warnings": []}
```

`window_start`/`window_end` зависят от момента запуска; остальные числа определяются
синтетическими данными. Личных данных в прогоне нет: точки, сенсор и записи решений
сгенерированы.

## 4. Проверка «токен не в логе»

1. Тест `test_import_summary_has_no_token` передаёт `--token tok-secret` и проверяет, что
   строки `tok-secret` нет в stdout; сводка при этом разбирается как JSON.
2. Тот же прогон с `--token` и `--password` проверен на трёх каналах: stdout, stderr и файл
   `--out`. Ни в одном нет токена, пароля и base URL.
3. Ошибки клиента проходят через `_redact`: `token=...` заменяется на `token=***`, а сам
   токен и `api-secret` — на `***` (покрыто `tests/test_nightscout_client.py`).
4. Расшифровка экспорта не печатает ни пароль, ни открытый текст: при неверном пароле
   выводится только «cannot decrypt export: wrong password or damaged file»
   (покрыто `tests/test_nightscout_prefs.py`).

## 5. Ограничения

1. **Нет exercise.** События, которых нет в классификаторе (в том числе exercise и
   произвольные заметки), попадают в трейс как `note`; их влияние на решения не
   воспроизводится.
2. **Нет кэша.** Импорт живёт только в памяти процесса. `--out` — единственная запись на
   диск, и только по явному запросу пользователя.
3. **Нет ретраев и пагинации.** Один запрос на endpoint с `count` из клиента (20000 точек,
   5000 лечений, 5000 devicestatus); при 401 клиент один раз повторяет запрос с
   `api-secret`, если он задан.
4. **Окно режется до 14 дней**; о срезе сообщается предупреждением в сводке.
5. **Нет проверки паритета решений.** `decisions` только импортируются; сверка с реальными
   решениями и допуски — W2.
6. Пустой `devicestatus` не останавливает импорт: выдаётся предупреждение
   «no devicestatus: parity check disabled».
7. CLI вызывает `status`, `profile`, `entries`, `treatments`, `devicestatus` последовательно,
   без параллельных запросов.

## 6. Файлы

- `python/nightscout/cli.py` — `main(argv)` и подкоманда `import`, сводка, `--out`.
- `python/nightscout/__main__.py` — запуск `python -m nightscout`.
- `tests/test_nightscout_cli.py` — тест сводки и отсутствия токена.
- `tests/nightscout_stub.py` — синтетический HTTP-стаб.
